# 小红书账号诊断 Skill

一个面向 Codex 的小红书账号数据复盘 Skill：读取创作者后台数据，通过三轮 AI 协作完成账号诊断、人工校准，并收敛出一个可验证的第一优先行动。

> 不是让 AI 替你拍脑袋给答案，而是让每个重要判断都能回到数据证据，并由你完成最终校准。

## 它解决什么问题

小红书后台的数据很多，常见的困难不是“没有数据”，而是：

- 不知道哪些数据最值得关注；
- 看到了多个问题，却找不到当前重点；
- AI 给出很多建议，但难以判断依据是否可靠；
- 得到诊断后，仍然不知道下一步具体做什么。

这个 Skill 会把账号资料、数据事实、诊断解释和行动建议分开处理，帮助你从复杂数据中收敛出一个优先验证的方向。

## 你会得到什么

- 一份资料读取与缺失项确认；
- 一份带证据定位、证据强度和优先级的诊断结果；
- 一次由你参与的人工校准；
- 一张可执行、可观察、可复盘的第一优先行动卡；
- 一套可以随着账号数据更新而反复使用的数据复盘方法。

## 三轮诊断流程

| 轮次 | 解决的问题 | 主要产出 |
|---|---|---|
| 第一轮：读取与确认 | AI 是否正确读懂了资料、目标和限制？ | 文件清单、数据范围、缺失项、账号目标复述 |
| 第二轮：分流与诊断 | 账号处于什么阶段，当前有哪些候选问题？ | 账号阶段分流、数据事实、证据定位、候选诊断和优先级 |
| 第三轮：人工校准与行动收敛 | 哪个判断值得采纳，下一步具体做什么？ | 校准后的判断和一张第一优先行动卡 |

默认情况下，每完成一轮都会等待你确认。你也可以使用快速模式连续完成三轮，但任何模式都不会省略中间轮次。

## 适用账号

支持以下小红书账号：

- 已发布一定数量内容、具备近 30 天数据的账号；
- 数据较少、仍在冷启动阶段的新账号；
- 内容方向较杂、需要先梳理定位的账号。

**当前仅支持小红书。** 不支持抖音、视频号或其他平台，也不会把小红书的数据字段和判断阈值套用到其他平台。

## 准备账号资料

尽量准备以下资料，并放在 AI 可以访问的同一个工作目录中：

- 笔记列表或笔记明细表；
- 近 30 天发布数据；
- 近 30 天观看数据；
- 近 30 天互动数据；
- 近 30 天涨粉数据；
- 账号主页截图，包括简介、粉丝数量等可见信息；
- 你的账号目标、目标用户、当前困扰和现实限制。

资料不完整也可以开始。Skill 会先指出缺失项及其影响，不会静默补全不存在的数据。

## 安装

### 方法一：让 Codex 安装

把下面这句话发给 Codex：

```text
帮我安装这个 Skill：https://github.com/liyaotangLEO/diagnose-xiaohongshu-account
```

### 方法二：手动安装

在 PowerShell 中运行：

```powershell
git clone https://github.com/liyaotangLEO/diagnose-xiaohongshu-account.git "$env:USERPROFILE\.codex\skills\diagnose-xiaohongshu-account"
```

安装完成后，重新打开一个 Codex 任务，让 Codex 发现新 Skill。

## 快速使用

### 默认模式

适合首次诊断、课堂实操，或希望逐轮检查 AI 是否读对数据的情况：

```text
使用 $diagnose-xiaohongshu-account 读取当前目录中的小红书账号资料，跟我逐轮完成账号诊断，并收敛出一个第一优先行动。
```

### 快速模式

适合已经熟悉流程、希望一次看到完整结果的情况：

```text
使用 $diagnose-xiaohongshu-account 诊断当前目录中的小红书账号资料。采用快速模式，连续完成三轮，但不要省略任何轮次、证据定位、不确定性和人工复核提醒。
```

快速模式只是跳过轮次之间的等待，不代表 AI 的判断不需要人工校准。

## 输出示例

下面是压缩后的结构示例，实际输出会引用你的本地文件和数据：

```markdown
### 候选诊断 1：主页承接不足

- 数据事实：近 30 天有 126 次主页访问，新增关注为 0。
- 证据定位：近30天涨粉数据.xlsx｜账号趋势｜主页访问人数、新增关注人数｜近30天
- 诊断解释：内容已推动用户进入主页，但主页信息没有有效完成关注转化。
- 证据强度：A
- 不确定性：缺少主页历史版本，无法仅凭当前资料证明简介是唯一原因。
- 候选行动：改写简介中的用户价值承诺，并观察下一周期主页访问转粉率。

### 第一优先行动卡

- 行动：本周只修改主页简介，明确目标用户和可获得的价值。
- 验证指标：主页访问转粉率。
- 观察周期：7 天。
- 继续条件：转粉率改善则保留新版简介；无改善则检查主页内容结构和关注理由。
```

### 文件职责

| 文件 | 作用 |

| [`SKILL.md`](SKILL.md) | 定义触发范围、交互模式、三轮流程、证据规则和异常处理 |

| [`references/xiaohongshu-inputs.md`](references/xiaohongshu-inputs.md) | 定义小红书资料类型、读取方法和证据定位格式 |
| [`references/diagnostic-protocol.md`](references/diagnostic-protocol.md) | 定义账号阶段分流、数据充分度、诊断结构和证据规则 |
| [`references/output-templates.md`](references/output-templates.md) | 定义三轮输出和第一优先行动卡的格式 |

### 设计边界

- 账号分流阈值是课程 V1 试行标准，不是小红书官方规则；
- 优先使用账号内部数据对比，不虚构行业基准；
- 证据强度表示“证据对判断的支持程度”，不是模型可信度，也不是行动成功概率；
- 相关性不能直接写成已经证实的因果关系；
- 扩展其他平台时，应单独整理平台字段、资料类型和判断逻辑，不能直接复用小红书协议。

## 注意事项

- 本 Skill 提供的是 AI 辅助复盘与行动假设，不是小红书平台官方诊断；
- 数据质量、统计周期和账号目标会直接影响诊断质量；
- AI 可能误读字段、图片或账号背景，必须通过第三轮人工校准修正；
- 第一优先行动需要通过后续数据验证，而不是被当作确定答案。
