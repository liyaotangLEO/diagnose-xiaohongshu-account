# 小红书账号诊断输出模板

## 目录

1. 第一轮读取确认
2. 第二轮账号分流
3. 第二轮候选诊断
4. 快速模式声明
5. 第三轮人工校准
6. 第一优先行动卡

## 1. 第一轮读取确认

```markdown
# 第一轮｜资料读取确认

## 平台
- 小红书确认依据：

## 已读取资料
| 文件 | 工作表/页面 | 字段与内容 | 记录数 | 时间范围 | 状态 |
|---|---|---|---:|---|---|

## 缺失、冲突或无法读取
-

## 对账号的理解
- 账号目标：
- 目标用户：
- 当前困扰：
- 运营阶段：
- 现实约束：

## 对后续诊断的影响
- 可以回答：
- 暂时不能回答：

## 请用户确认
请确认文件、时间范围、账号目标和现实约束是否正确，并直接纠正有误部分。
```

本轮不输出诊断和行动建议。

## 2. 第二轮账号分流

```markdown
# 第二轮｜账号阶段与运营诊断

## 账号阶段
- 运营时间跨度：
- 有效笔记数量：
- 数据完整度：0/1/2
- 数据充分度总分：0–6

## 内容分类
| 分类 | 目标用户 | 用户问题 | 内容主题 | 笔记数量/占比 |
|---|---|---|---|---:|

## 内容一致性
- 目标用户：0/1/2
- 用户问题：0/1/2
- 简介价值承诺：0/1/2
- 总分：0–6

## 最终分流
- 阶段：完整经营 / 完整经营轻量版 / 冷启动 / 定位诊断
- 分流依据：
- 本次能够回答：
- 本次暂时不能回答：
```

默认模式下，内容分类须先由用户确认，再将一致性分数视为最终结果。

## 3. 第二轮候选诊断

按优先级排列，每项使用同一结构：

```markdown
### 优先级N｜诊断标题

- 数据事实：
- 证据定位：`文件名｜工作表/页面｜行号或记录标识｜字段｜时间范围`
- 诊断判断：
- 待验证假设：
- 影响环节：
- 证据强度：A / B / C
- 不确定性：
- 候选行动：
- 验证指标或观察方向：
```

第二轮可以推荐排序，但不替用户最终决定行动。

## 4. 快速模式声明

连续完成三轮时，在第三轮前加入：

> 本次采用快速模式，中间结果未经用户逐轮确认。涉及账号定位、数据口径和现实约束的判断，需要用户后续复核。

快速模式仍完整展示第一轮、第二轮和第三轮。

## 6. 第一优先行动卡

最终只输出一张：

```markdown
# 第一优先行动卡

- 当前最值得处理的问题：
- 关键数据事实：
- 证据定位：
- 证据强度：A / B / C
- 准备验证的假设：
- 最小行动：
- 执行边界：本次明确不做什么
- 观察指标：
- 开始时间：
- 复盘时间：
- 继续标准：什么结果代表值得继续
- 调整标准：什么结果代表需要修改或停止
```

行动类型随账号阶段变化：

- 完整经营诊断：验证一个流量或转化假设。
- 冷启动诊断：完成一轮有目的的内容实验。
- 定位诊断：完成能力、用户和候选方向盘点。
